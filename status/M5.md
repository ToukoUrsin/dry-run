## Nemotron curriculum machinery (expert tuning gate)

The v4 provider responses were deduplicated by `rollout_id` (highest retained
attempt) into `/bulk3/runs/dryrun/m5/nemotron_accuracy_v4_diagnoses.jsonl`
(300 records). `dryrun.curriculum.scene_specs` accepted all 300 records. Until
a learned-policy checkpoint is ready, the required equal-size comparison was
run through the measured MuJoCo expert tuning hook on four suggested scenes
and four random scenes:

```text
MUJOCO_GL=egl OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=. \
  .venv/bin/python -m dryrun.curriculum \
  --diagnoses /bulk3/runs/dryrun/m5/nemotron_accuracy_v4_diagnoses.jsonl \
  --size 4 --seed 7 --measured-expert \
  --out /bulk3/runs/dryrun/m5/curriculum_expert_tuning_v2-20261115-size4.json
```

Source commit at command start: `bd6fc4328d9fbb4d33716cab92a30fc233fcb6f4`.
The result is `/bulk3/runs/dryrun/m5/curriculum_expert_tuning_v2-20261115-size4.json`:
the Nemotron-suggested scenes sorted 9/24 bricks (`0.375000`), while the
random control sorted 15/30 (`0.500000`). The comparison has four scenes in
each arm; its brick denominators differ because the generated scene batches
have different counts. Delta is `-0.125000`, `helps=false`. This is tuning
evidence only; it is not a learned-policy result or held-out benchmark, and
the negative delta is reported rather than hidden. The same artifact is the
baseline to replace when a policy checkpoint can train and score both batches.
