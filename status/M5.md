The analyst loop is implemented and exercised against the real NVIDIA endpoint. The

Source commit used for the proof commands below: `40d23d4`.

## Camera-only Nemotron request

The client is `dryrun/nemotron.py`, model
`nvidia/nemotron-3.5-super-vl-120b-a12b`, endpoint
`https://integrate.api.nvidia.com/v1/chat/completions`. It selects six frames,
balanced between top and inspection cameras, and sends no event labels or hidden
scene fields. It validates the exact stage/cause/frame/features/next-scenes schema,
keeps every request and raw response, and retries invalid output with backoff.
The few-shot version includes two camera-only format examples.

```text
hsec exec --only NVIDIA_API_KEY -- .venv/bin/python -m dryrun.nemotron \
  --frame /bulk2/runs/dryrun/m1/frames/top_view.png \
  --frame /bulk2/runs/dryrun/m1/frames/inspection_view.png \
  --frame /bulk2/runs/dryrun/m1/frames/top_view.png \
  --frame /bulk2/runs/dryrun/m1/frames/inspection_view.png \
  --frame /bulk2/runs/dryrun/m1/frames/top_view.png \
  --frame /bulk2/runs/dryrun/m1/frames/inspection_view.png \
  --rollout-id seed7-m5-v4-fewshot --out /bulk2/runs/dryrun/m5/live006
-> response.json: attempt=1, stage=knocked_neighbour, frame=frame-03.png,
   one-sentence cause, one valid messy scene spec

same command with --rollout-id seed7-m5-v4 --out /bulk2/runs/dryrun/m5/live005
-> response.json: attempt=3; raw_response_0.json through raw_response_2.json
   are retained, then a strict stage=drop diagnosis was accepted
```

The complete request/response pairs are under
`/bulk2/runs/dryrun/m5/live005/seed7-m5-v4/` and
`/bulk2/runs/dryrun/m5/live006/seed7-m5-v4-fewshot/`. A diagnosis is stored by
`dryrun.nemotron.store_diagnosis` through `telemetry.record_diagnosis`; the local
Timescale check returned two rows, including `seed7-m5-v4-fewshot`. The shared
`failure_diagnoses` schema and `/api/failures` expose frame paths, the sentence,
and next-scene specs.

## Labelled set and scoring

```text
python - <<'PY'
# select the first 300 failed rows from the real reach-map event log
# -> data/failures300.jsonl, rows=300
PY
.venv/bin/python -m dryrun.nemotron_score \
  --events data/failures300.jsonl \
  --predictions /bulk2/runs/dryrun/m5/predictions_parser_control.jsonl \
  --labels-out /bulk2/runs/dryrun/m5/failures300.labels.jsonl \
  --output /bulk2/runs/dryrun/m5/parser-control-score.json
-> n=300, stage_accuracy=1.0, cause_accuracy=1.0, accuracy=1.0
```

That 1.0 result is a scoring-pipeline control made by replaying the event-label
mapper against its own labels. It is deliberately not called Nemotron accuracy.
The actual provider sample is saved and validated; a full version-by-version
provider score still requires one saved camera set and response per labelled
failure.

| version | change | accuracy |
| --- | --- | ---: |
| v1-one-frame | legacy one-frame path; rejected by the six-frame contract | not measured |
| v2-both-cameras | top plus inspection frames | not measured |
| v3-observation-chain | both cameras plus written observation chain | not measured |
| v4-both-chain-fewshot | both cameras, chain instruction and two format examples | provider sample saved; n=3, no aggregate accuracy |
| parser-control | event-label mapper sanity check, 300 real failure rows | 1.000 (control, not Nemotron) |

## Curriculum and stations

```text
.venv/bin/python -m dryrun.curriculum \
  --diagnoses data/nemotron_live005.jsonl --size 1 \
  --out /bulk2/runs/dryrun/m5/curriculum_live005.json
-> checkpoint=expert-tuning-v0, batch_size=1, suggested score=1.0,
   random score=1.0, delta=0.0, helps=false
```

The comparison enforces equal batch size and one named checkpoint. The current
policy checkpoint is not a completed held-out policy, so this is explicitly the
expert tuning smoke hook; it does not claim an uplift.

```text
MUJOCO_GL=egl .venv/bin/python -m dryrun.stations \
  --out-dir /bulk2/runs/dryrun/m5/stations36_proof \
  --record /bulk2/runs/dryrun/m5/stations36_proof.jsonl --count 3
-> attempted=36, accepted=36, rejected=0, pass_rate=1.0

# 36 isolated expert calls through dryrun.render.rollout
-> expert_runs=36, bricks=108, successes=6, expert_score=0.0555556
```

The 36 input sentences are distinct. Each accepted station passed MuJoCo load,
rest-intersection, reachability and camera checks; the JSONL records are in
`data/stations36.jsonl` and `data/stations36_expert.jsonl`. Rejected XML and
reasons are retained by `dryrun.stations` whenever a sentence fails generation
or validation. The queue path required by the Soren follow-up is proven by
`dryrun.worker --once`: request 1 and request 2 were accepted, each ran one
three-brick expert station, and `worker_heartbeat` reported `online`.

A full-tree `codex review --uncommitted` was run before integration. The CLI
could not inspect the tree because its MCP command runner requested approval
under the repository's `approval=never` policy; `git diff --check` and Python
compileall both passed. The failed review invocation is recorded rather than
claimed as a green review.
